## 코드 프로젝트 추가 규칙

- **문서가 진실이다.** 스펙과 구현이 어긋나면 문서 우선. 구현 중 스펙 결함을 발견하면 코드로 우회하지 말고 문서 수정 + problem 기록을 먼저 한다.
- 커밋은 작업 단위(journal)로. 문제 해결 커밋은 본문에 `P-NNN`을 남긴다. 푸시는 사용자가 요청할 때만.
- 실험·측정은 스크립트로만 실행해 재현 가능하게 한다. 수동 실행했다면 명령을 journal에 그대로 남긴다.
- 외부 API·프로토콜·포맷 변환을 다루면 **골든셋이 "완성"의 정의**다: 실 응답을 새니타이즈해 `fixtures/`에 녹화 → 테스트는 픽스처 재생만(네트워크 금지) → 스냅샷 비교. 하네스는 변환기와 동시 또는 선행으로 만든다.
- 빌드·테스트·실행 방법은 `wiki/howto/`에 둔다.
